# Contributing

## Workflow

1. Fork and branch from `main`.
2. Make changes. Run `make check`.
3. Open a PR and fill every section of the template.

## Issues

Bugs: include Rust version, OS, reproduction.
Features: describe the use case before the proposed API.

## Commit messages

Conventional Commits: `feat:`, `fix:`, `docs:`, etc.
Breaking changes: `feat!: ...`.
The body says why the change exists and what breaks without it.
